# Food Log

<img src="src/main/resources/logo.png" alt="Food Log 图标" width="128" height="128">

[English](README.md) | **中文**

**这是一个纯客户端模组，适用于 Forge 1.20.1，使用 Java 21 构建。**

食物图鉴会把游戏里所有食物列出来，判断哪些你已经吃过、哪些还没吃过，让整合包里成百上千种
料理不再是一笔糊涂账。

> **纯客户端模组。** 只需要装在客户端，**服务端无需安装**，也不需要知道它的存在。把 jar 丢进
> 客户端的 `mods` 目录即可，单机、原版服务器、Forge 服务器、各种整合服都能直接用。它只读取
> 服务端本来就会发给每个客户端的信息，也只做普通玩家会做的操作（开界面、点格子、使用手里的
> 物品）。

## 运行环境

| | |
|---|---|
| Minecraft | 1.20.1 |
| 模组加载器 | Forge 47.x（开发时使用 47.2.0） |
| 运行端 | **纯客户端** —— 不要装到服务端 |
| 构建环境 | **Java 21**（字节码为 Java 17，所以在 Java 17 实例上也能跑） |
| 可选 | JEI（用于 `%未吃` / `%uneaten` 搜索别名） |

## 主要功能

- **食物图鉴界面** —— 翻页网格列出全部食物，并带分维度标签栏。用快捷键 `Open Food Log`
  或 `/foodlog page` 打开。
- **五个分类维度** —— 类型、生熟、来源、饱食、条件，每个维度有各自的筛选标签页，可以直接跳到
  「生鱼」「低饱食度料理」这类目标，不用在字母序列表里翻找。
- **一眼看出吃没吃过** —— 已吃过显示绿色，未吃过显示灰色。
- **导入原版统计** —— 装这个模组之前已经吃过几百种东西？导入按钮会读取原版的进食统计并回溯进
  图鉴。这些条目显示为青色，因为统计只能证明物品「被用过」，不能证明「被吃过」。
- **容器高亮** —— `/foodlog lighting true` 会在任意容器界面里给未吃过的食物描上金边、同时把其余
  物品压暗，让一箱子杂物里真正值得拿的东西凸显出来。兼容原版容器、mod 容器和精致存储网格。
- **「取未吃各1」按钮** —— 容器界面角落里的可拖动按钮，把容器里每种未吃过的食物各取 1 个直接放进
  背包。
- **JEI 搜索别名** —— 在 JEI 里搜索 `%未吃`（或 `%uneaten`），只筛出还没吃过的食物。
- **自动进食** —— 可选功能，模组会替你吃掉没吃过的食物，按饱食度从低到高吃，让一条饥饿条能容下
  尽可能多种不同的食物。实现方式是把食物用数字键交换到手上、使用、再换回原位，背包最终保持原样。
  标记为「随时可吃」的食物会被正确识别；只有真的吃下去了才会被记录。

## 指令

所有指令都是**客户端指令** —— 在任何服务器都能用，服务端完全看不到。

| 指令 | 作用 |
|---|---|
| `/foodlog` 或 `/foodlog page` | 打开食物图鉴界面 |
| `/foodlog lighting` | 切换容器高亮 |
| `/foodlog lighting <true\|false>` | 明确设置容器高亮 |
| `/foodlog eat` | 切换自动进食 |
| `/foodlog eat <true\|false>` | 明确设置自动进食 |
| `/foodlog eat now` | 立刻把身上所有没吃过的食物各吃一遍 |

自动进食只在没有打开任何界面时自行运行，所以开箱子不会在背后偷偷吃东西。`/foodlog eat now`
则是刻意允许在容器打开时工作，这样也能吃到容器里的东西。

## 安装

1. 在客户端安装 **Forge 47.x for 1.20.1**。
2. 把 `foodlog-<版本>.jar` 放进客户端的 `mods` 目录。
3. 就这样。不要装到服务端。

## 数据存储

全部数据都在客户端。你玩过的每个服务器（以及每个单机存档）都会有各自独立的文件，放在
`config/foodlog/` 下，以服务器地址或存档名区分，所以同一种食物在 A 世界可能算「吃过」、在 B
世界算「没吃过」。界面偏好设置存在 `config/foodlog/settings.json`。

卸载模组不会删除这些文件，删掉它们也只是丢掉图鉴记录。

## 从源码构建

需要安装 **JDK 21**。Gradle 8.1.1 本身必须跑在 JDK 17 上（它读不了 Java 21 的 class 文件）——
`gradle.properties` 里的 `org.gradle.java.home` 指向了一个 JDK 17，把它改成你自己的 JDK 17
路径，或者升级 Gradle 后删掉这一行。

```powershell
.\gradlew.bat build
```

产物在 `build/libs/`。

> JEI 是 `compileOnly` 依赖，从 `libs/jei-1.20.1-forge-15.20.0.106.jar` 解析，这个 jar 没有提交到
> 仓库。如果你想编译 JEI 集成部分，请自行下载 1.20.1 Forge 的 JEI jar 放到该路径。JEI 在运行时
> 是可选的，没有它模组照常工作，只是少了搜索别名。
